## 一、问题① 处置：fortification.js 直接 import core/facility.js 的边界问题

**结论：不批准例外，采用「补充统一 Context API」方案（v1.1）。**

- `factionContext.js` 补全 8 个能力：
  - 设施维护/查询：`expireFacilities / getFacilitiesByOwner / getFacilitiesByType / getFacilitiesInRange / getAllFacilities`
  - 决策查询：`getPendingDecisions`
  - 纯函数转发：`diagonalDist / movementCost / areAllies`（core 纯函数同样经 ctx 转发，避免各联盟 import 路径分叉）
- `fortification.js` 已移除对 `facilitySystem / decisionSystem / movement / teams / utils` 的全部直接 import，统一改为 `ctx.xxx`。
- 契约 `FACTION-SYSTEM-API-CONTRACT.md §5` 已新增**强制边界规则**：联盟系统禁止直接 import 任何 core/ 状态性模块；能力缺口向主对话申请补入 context，不得自行绕过。后续金帐/威尼斯/马穆鲁克/大明一律照此执行。

## 二、问题② 处置：beforeMove 埋点

**已由主对话统一补充**（main.js `moveUnit` 内、`unitEntry.x = x` 之前）：

```js
const movePayload = { unit: unitEntry, from: { x: unitEntry.x, y: unitEntry.y }, to: { x, y }, cancel: false };
eventBus.emit('beforeMove', movePayload);
if (movePayload.cancel) return false;
```

- 位置在移动生效前、扣移动力前，与契约 §2.2 一致；payload 增加 `cancel:false` 初始字段。
- 无订阅者时事件空转、`cancel` 恒 false → 原移动逻辑与 RNG 调用顺序零变化（已由 seed777 逐项一致证明）。

### 4. 固定 seed 结果是否变化

**完全一致（零变化）。**

`node sim/run.js map=strait diff=brutal agg=balanced rounds=1 seeds=777`：
- 胜者 C（ai1）、回合 121、stalls1941/reroutes224/retreats89/cityCaptures8/oilCaptures3/shipyardCaptures2/engineerLandings71/transportLaunches6/campsBuilt0/sells301，byOwner 逐项与基线相同。

**为什么零变化（需解释）**：sim 中无 `player` owner → 神罗建造决策不发起（`owner==='player'` 分支）→ 无任何工事 → 木栅税/工事效果/阵线全不触发；兵种联动（长矛方阵/近卫军/攻城塔）需 AI 部署对应兵种且满足条件，在本次 seed777 对局中未改变终局统计。

**注意**：sim 里所有 AI 默认 `faction:'hre', nation:'austria'`（`$('ai0Faction')?.value || 'hre'` 回退）。这意味着：
- 当前所有 sim 场景的 AI 实际全是神罗（v0.1.2 起即如此，非本次引入）；
- 后续联盟（金帐等）接入后，sim 仍只会测到神罗路径——**建议后续在 sim/run.js 增加 `ai${i}Faction/Nation` 注入支持**，否则联盟差异化无法在无头环境验证（本期记录为待办，不擅自改动 sim 配置）。
