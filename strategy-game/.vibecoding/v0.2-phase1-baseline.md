## 五、核心数据结构基线

### unit（13 字段）
```
{id, type, owner, x, y, hp, maxHp, move, maxMove, baseMove,
 acted, hasAttacked, lastAttacked, kills, rank, cargo}
```
- 经验系统：kills → rankFromKills(UNIT_RANK_THRESHOLDS) → rank；rank 影响移动(effectiveMove)和回血(healMultiplier)；马穆鲁克 kills×2。

### site（9 字段 + 可选）
```
{id, kind, owner, x, y, name, tier, income,
 duration?(camp), uncapturable?(camp), _caravanBonus?(拉古萨)}
```
- camp 是临时据点：duration 每回合衰减（decayTemporarySites），uncapturable，被敌方踩即摧毁。

### game（核心字段）
```
{w, h, terrain, units[], sites[], ownerOrder, currentIndex, side, turn,
 selected, over, logs, teams, ownerColors, aiProfiles, aiFrontMemory,
 goldByOwner, stats, settings, buildsThisTurn?, pendingOrder?, freeplay?}
```

## 七、存档结构基线

- 后端：localStorage（src/io/storage.js 封装 saveStore）
- 序列化：buildSavePayload() → `{name, savedAt, map, turn, W, H, S, state: game对象(排除selected/pendingOrder)}`
- **Phase 1 约束：不改变此结构。** 基础设施状态用模块内部变量，不挂 game，不进入存档。阶段 2 有持久化需求时再单独设计存档扩展与旧档兼容。

## 八、RNG 基线

- 随机数：src/core/rng.js（确定性 LCG），combat.js 用 `rnd(3)` 做伤害浮动。
- **Phase 1 约束：埋点不得插入任何 rnd() 调用，不得改变现有 rnd() 调用顺序。** 固定 seed 单局的终局数字完全一致是 RNG 未被扰动的硬证据。
