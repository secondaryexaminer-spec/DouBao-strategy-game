## 0.1 系统加载路径（重要，开工前必读）

**你写的 hre 模块不会被自动加载。** 当前架构下：

- `src/factions/factionRegistry.js` 定义了 `register(factionId, system, ctx)`，但**目前没有任何调用点**（阶段1刻意如此，保持零行为变化）。
- esbuild 只打包从 main.js 可达的 import 链。你的 `src/factions/hre/hreRules.js` 如果不被 main.js import，**不会进入构建产物**，游戏运行时代码根本不存在。

**加载（接线）由主对话在集成时统一完成**，你不需要也不允许自己做。主对话的接线方式（供你了解，不要实现）：

```js
// main.js 顶层（主对话在集成时添加）
import { createFactionContext } from './factions/factionContext.js';
import { factionRegistry } from './factions/factionRegistry.js';
import { hreSystem } from './factions/hre/hreRules.js';

// main.js 闭包内（主对话在集成时添加，幂等，只注册一次）
function initFactionSystems() {
  if (factionCtx) return factionCtx;
  factionCtx = createFactionContext({
    gameRef: () => game,
    getUnit, getSite, typeMeta,
    terrainMeta: (k) => TERRAIN[k],
    ownerFaction, ownerNation,
    log, addGold, spendGold,
  });
  factionRegistry.register('hre', hreSystem, factionCtx);
  return factionCtx;
}
// 在 newGame 内、startFirstTurn()（第一次 turnStart emit）之前调用 initFactionSystems()
```

**你如何自测自己的代码（不碰 main.js）**：写一个临时 harness（ES module，`.mjs` 扩展名，Node 直接可跑），用 `createFactionContext` + 伪造的 deps + `factionRegistry.register` 临时注册你的系统，然后模拟事件触发验证逻辑。harness 是临时测试文件，交付报告里注明，主对话接线后删除。示例骨架见 §5.8。

**验收标准的划分**：
- 你的交付验收 = hre 模块逻辑正确（harness 自测证明）+ 不破坏 main.js（`npm run build` 仍通过）。
- sim 终局验证 = **主对话接线后**做，不属于你的验收（因为你的代码还没被加载进产物）。主对话会验证：非神罗局零变化、神罗局差异可解释。

## 3. 你的任务：神罗工事系统

### 3.1 核心目标

让神罗玩家的核心决策变成：**"在这里建工事吗？建哪种？防线连起来了吗？"**

规格书§3 的核心循环：
```
占领关键位置 → 建设工事 → 形成防线 → 敌人进攻 → 高防御单位与工事消耗敌军 → 重型部队反攻 → 推进第二条防线
```

### 3.2 三种工事（用 facility.js 创建）

| 工事类型 | type 字符串 | 成本 | 持续 | 效果 |
|---|---|---|---|---|
| 木栅 | `'palisade'` | 低（建议10-15金币） | 5回合 | 敌军进入需额外移动消耗（+1）；神罗步兵在其上防御+2；可被攻击摧毁（hp建议8） |
| 壕沟 | `'trench'` | 中（建议15-20金币） | 8回合 | 降低敌方骑兵冲锋效果（charge值-2，最低0）；降低敌方第一轮攻击伤害-2；hp建议12 |
| 石堡 | `'stoneFort'` | 高（建议30-40金币） | 不过期（duration=null） | 大幅提升驻守单位防御+4；为相邻远程单位提供防御+2；可作为临时补给节点（相邻单位回血+1）；只能建在城市/军营/堡垒相邻2格内；hp建议30 |

> 数值为建议起点，你可根据测试调整，但必须在交付报告中列出最终数值。

### 3.3 建造方式

神罗的**步兵单位**（domain='land' 且非骑兵，即 typeMeta.charge 为 falsy 的陆军）在满足条件时可以建造工事：
- 单位未行动（acted=false）
- 当前格子无其他工事（getFacilityAt 返回 null）
- 金币足够
- 石堡需在城市/军营/堡垒相邻2格内

建造消耗：金币 + 单位本回合行动（acted=true，移动归零）。

**UI 注意**：阶段2不做最终 UI。你需要提供一个 debug/test 入口（如全局函数或键盘快捷键）让测试者能触发建造。或者，更简单：神罗步兵在有金币且未行动时，自动在当前格建木栅（但这违反"主动机制保留决策点"原则）。

**正确做法**：用决策API（decision.js）提供建造选择：
- 神罗步兵选中时（或回合开始时），如果满足建造条件，调用 `requestDecision` 提供选项：[建木栅/建壕沟/建石堡(如满足条件)/不建]
- 无头 sim 环境自动选"不建"（test fallback），所以 sim 不会自动建工事，零行为变化
- 阶段7 UI 再做真实建造按钮

这样既保留了玩家决策点，又不影响 sim 基线。

### 3.4 阵线机制（frontlineScore）

当神罗在连续区域形成稳定防线时，获得"阵线稳定"效果：
- 检测：每个神罗工事，检查其相邻4格是否有神罗控制的据点（sites owner=神罗方）或其他神罗工事。连续3格以上的工事/据点链视为"阵线稳定"。
- 效果：
  - 阵线上的工事耐久+20%（hp×1.2，取整）
  - 阵线上驻守的神罗单位每回合回血+1
- 实现：在 turnStart 事件中，遍历神罗工事，计算阵线状态，用 status.js 给相关单位加 `'frontline'` 状态（turns=1），或直接在 facility 的 data 里标记 `data.frontlined=true`。

### 3.5 兵种联动（规格书§4）

在工事系统基础上，以下神罗兵种获得联动效果（用事件钩子实现，不改 constants 数值）：

| 兵种 | 联动效果 |
|---|---|
| 德意志重甲步兵 | 驻扎在工事上时获得"坚守"：防御+2，被骑兵攻击时额外防御+1（用 beforeAttack 钩子） |
| 长矛方阵 | 相邻至少1个友军步兵时，获得"方阵"：第一次受到近战伤害-2（用 beforeAttack 钩子，defender 是长矛方阵时） |
| 帝国近卫军 | 守点时为同格或相邻神罗单位提供"皇家守护"：防御+1（用 beforeAttack 钩子，检查 defender 相邻是否有帝国近卫军） |
| 攻城塔 | 在据点战中降低驻军防御-2（用 beforeAttack 钩子，attacker 是攻城塔且 defender 在据点上时） |

> 这些是规格书§4的要求。现有兵种效果（长矛方阵免冲锋、帝国近卫军守点+3、攻城塔占领返还移动）已在 main.js/combat.js 实现，**保留不动**，你只新增上述联动效果。
