## 4. 新增事件 Hook（5 个，全部 `system[hook](ctx, payload)` 签名）

| 钩子 | 触发时机 | payload | 是否可取消 |
|---|---|---|---|
| `onTurnStart` | 每回合开局（`{owner, initial}`） | 埃及尼罗河补给 +2 回血；巴格达整军 +1 回血；发起学者四选一决策；清 fireline / 每回合首攻标记 | 否 |
| `onBeforeMove` | 单位移动前 | `{unit, from, to, cancel}` | 否（机动战术不取消移动，仅预支移动力） |
| `onBeforeAttack` | 攻击结算前（previewCombat 后） | `{attacker, defender, fromCell, toCell, result:{damage,counter}, isCounter, cancel}` | 否（改 `result.damage`，引用传递，按注册顺序 hre→gh→venice→mamluk 叠加） |
| `onAfterAttack` | 全部战斗处理后 | `{attacker, defender, result, defenderDead, attackerDead}` | 否（经验/士气/eliteLost 主入口；**不依赖 unitKilled**，规避 GH-09） |
| `onSiteCaptured` | 占领 | `{unit, site, oldOwner}` | 否（+15 XP） |

## 5. 新增玩法

- **精锐成长**：特殊单位集合 = `mamlukCavalry / camelWarrior / sultanGuard`（规格书 §9.1"精锐骑兵=战略资产"的骑兵三类）。经验来源：造成伤害（1 XP/点）、击杀（+10）、关键战斗击杀 level≥3 目标（+5）、占领（+15）；埃及河边 ×1.5、高士气 ×1.5，乘法叠加（round）。
- **等级**：V1=30（攻击+1，自动）→ V2=70（防御+1，自动）→ **V3=120 三选一（`ctx.requestDecision`：冲锋强化=满移动力攻击+3 / 击杀回血=击杀+2 / 移动力强化=baseMove 永久+1）** → Elite=200（称号挂点，无数值）。
- **eliteLost**（veteranLevel≥3 死亡）：金币 -15 + 该 owner 士气 -3 + 经验清零（dead 标记、历史 kills 保留）——玩家在"再打一仗多拿经验 vs 死了赔钱赔士气"间自行权衡。
- **军团士气**：精锐击杀 +1 / 精锐死亡 -3；高（≥70）= 经验 ×1.5 + 特殊单位每回合首次攻击 +2（口径：**每回合首次**，回合重置）；低（≤30）= 新生兵（无档案）攻击 -1。
- **埃及（egypt）**：位于 `water`（河流）或己方 city 邻域（Chebyshev≤1）的特殊单位每回合 +2 回血。
- **叙利亚（syria）**：同一目标本回合第二个**不同**远程攻击者获得协同射击 +2（回合重置）。
- **巴格达（baghdad）**：学者每回合四选一（`ctx.requestDecision`，fallback 第一项=守势）：守势=被攻击 -1 / 进攻=攻击 +2 / 机动=每回合首次移动消耗 -1（预支实现）/ 整军=每回合 +1 回血。范围 Chebyshev≤3（与 combat.js 学者光环口径一致）。

## 附：经验教训（VibeCoding，建议主对话写入 `.vibecoding/MEMORY.md`）

1. harness 喂 XP 用 `typeMeta(unit.type).level` 判定关键战斗——**unit 对象显式覆盖 `level` 字段无效**（typeMeta 取 TYPES 常量），喂 XP 目标必须选 level≥3 兵种。
2. `freshGame` 后先 `setMoraleForTests` 再触发钩子会被钩子内 `syncGameRef` 清空——测试里跨局重置应显式调 `vet.syncGameRef(ctx)` 后再设状态。
3. decision 记录结构是 `{id, context, ...}`，**options 在 `context.options`**，harness 取选项需解包。
4. 决策 fallback（无 UI 自动选第一项）是"无头 sim 零变化"验收线的保证，第一项必须是默认/不行动。
