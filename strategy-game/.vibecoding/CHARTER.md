# 项目宪章 · 边境指挥官 / Frontier Commander

> 依据 vibe-coding 协议（铁律 2）建立。每个会话开局先读本文件与 MEMORY.md；与用户当场指令冲突时，以当场指令为准并在改动清单中注明。

## 1. 初衷
- **要解决的问题**：做一个可玩、可平衡、可长期迭代的回合制陆海联合作战策略游戏（纯前端，无后端）。
- **明确不做的事**：不引入后端/数据库；不引入框架依赖（当前仅 esbuild 一个 devDependency，保持零运行时依赖）；不做手机端适配的大改（除非用户明确要求）。
- **成功的长相**：双击 `index.html` 即可开局；AI 有决策可读性（战斗日志/统计图）；平衡性可用无头模拟验证。

## 2. 长期规则
1. **VibeCoding 4 条铁律默认生效**：每轮收尾三件事 / 宪章长期遵循 / 分支任务分对话 / 黑箱报错切段验证（详见 `.vibecoding` 所属 vibe-coding 与 blackbox-debugging 两个 skill）。
2. **改完源码必须重新构建**：`src/main.js` 是唯一逻辑源，改后必须 `npm run build`，`js/game.js` 是分发产物——历史教训：曾出现 game.js 比 main.js 旧 6 分钟的过期产物。
3. **AI 逻辑零分叉**：新增/修改 AI 行为必须让无头模拟（`sim/`）走同一打包产物 `js/game.js`，禁止另写一套"测试用 AI"。
4. **平衡性改动跑回归**：涉及数值/经济/胜利条件的改动，至少跑 `npm run sim:suite` 确认 4 个场景不回归。
5. **硬编码路径必须与实际一致**：页面里出现的存档/资源路径要跟真实目录核对（历史坑：index.html 中曾残留旧路径 `E:\WorkPlace\VScode workplace\...`，实际项目已迁移）。
6. **回合上限与规模意识**：默认 120 回合上限；改动胜利判定/回合逻辑时先查 `checkEnd()`、`resolveStalemate()`、`MAX_TURNS`，避免拖死对局。
7. **AI 难度设计原则**：以**冷酷难度为训练/调参基准**，中等和简单通过降智参数（lookahead / economy / production / risk）派生，不单独写三套 AI 逻辑；改进 AI 算法时先在冷酷难度上验证策略有效性，再确认降智曲线合理。
8. **重构与模拟器升级是长期贯穿性工作**：不设"100% 重构完成才能开始新功能"的前置门槛。地基重构（模块拆分）和模拟器升级随新功能需求驱动——做新兵种/AI 改良时遇到需要拆分的模块就拆，需要模拟器能力就升级。两者贯穿整个项目生命周期。

## 3. 边界与约束
- 技术栈：原生 HTML + CSS + Canvas 2D + ES Modules（esbuild 打包成 IIFE）；Node 仅用于构建与无头模拟。
- 存档：localStorage（快速读）+ 文件导出/导入（长期保存，`.frontiersave.json`）；`src/io/storage.js` 是抽象层，换文件后端时保持 `getItem/setItem/removeItem/keys` 同步 KV 接口不变。
- 不降级项：游戏逻辑改动必须能通过无头模拟验证，不能只靠"目测能跑"。
- 数字口径：涉及经济/数值的论断必须以 `constants.js` 中数值与代码运算为准，不凭印象。

## 4. 验收标准
- 逻辑改动：`npm run build` 成功 → `node sim/run.js rounds=10` 无异常跑完 → 相关场景 `sim:suite` 通过。
- UI 改动：浏览器打开 `index.html` 验证目标交互；渲染相关改动检查缩放/平移/选中高亮不受影响。
- 存档改动：导出 → 重载 → 导入，能恢复到存档时刻状态。
- 提交前：工作区干净，构建产物与源码时间戳一致。
