## 2. 马穆鲁克任务范围

你只负责**马穆鲁克联盟模块**（`src/factions/mamluk/`），不负责最终接线（接线由主对话完成）。

### 核心系统：精锐成长 + 士气（Layer 4）

依据规格书 §9/§10/§39 实现，**以本文件为准**（规格书与既有架构冲突时以本文件 + 契约为准）。

**精锐等级（veterancy，§39 数据结构 `{unitId, xp, veteranLevel, kills, lastPromotionTurn}`）**：
- 经验来源：造成伤害 / 击杀 / 占领 / 完成关键战斗。
- 等级：Veteran 1（攻击 +1，自动）→ Veteran 2（防御 +1，自动）→ **Veteran 3 三选一晋升（玩家决策）**：冲锋强化 / 击杀回血 / 移动力强化 → Elite（联盟特殊称号，不一定是数值，可为挂点/称号展示）。
- "特殊单位"集合（适用 veterancy）：从规格书 §9.1 上下文 + `src/core/constants.js` 马穆鲁克兵种确定，在交付报告中列明你采用的集合。

**精锐死亡代价（eliteLost）**：3 级以上（veteranLevel≥3）精锐死亡 → 金币损失 + 军团士气 -3 + 该单位累计经验清零。这形成用户点名的核心决策："**这个精锐要不要冒险继续战斗？**"——玩家要权衡"再打一仗多拿经验" vs "死了赔钱赔士气"。

**军团士气（mamlukMorale，模块级状态）**：
- 精锐击杀 +1 / 精锐死亡 -3。
- 高士气：精锐经验获取更快 + 骑兵第一次攻击增强。
- 低士气：新生兵攻击下降 + 精锐单位恢复降低（**恢复降低部分有接口缺口，见 §4-5**）。

### 三个国家机制（1~3 个/国）

- **埃及（egypt）**：尼罗河补给——位于河流/城市附近的马穆鲁克精锐每回合额外回血 + 经验获取增加（适合养长期精锐）。
- **叙利亚（syria）**：长弓火线——连续两个远程单位攻击同一目标时，第二个获得"协同射击"伤害提升（鼓励成规模远程）。
- **巴格达（baghdad）**：学术指令——哈里发学者每回合可选一种战术（**守势 / 进攻 / 机动 / 整军**），取代永远"攻防 +1"；这就是用户硬约束点名的"**学者四选一战术指令**"，必须是玩家决策点。

### 玩家决策点（用户硬约束，必须保留）

| 决策 | 形态 |
|---|---|
| Veteran 3 三选一晋升 | `ctx.requestDecision`（冲锋强化/击杀回血/移动力强化） |
| 学者四选一战术指令 | `ctx.requestDecision`（守势/进攻/机动/整军） |
| 精锐是否冒险继续战斗 | 不一定是显式决策框——通过"死亡惩罚机制"让玩家自己权衡；若你想做成"开战前确认"，也必须是 requestDecision 形态，禁止 autoChoose |

无头 sim 自动选选项第一项（如"冲锋强化"/"守势"），保证不传联盟参数的默认局零行为变化（参考 HRE/GH/Venice 的 fallback 设计）。

## 4. 关键接口评估（马穆鲁克专属，务必先读）

1. **经验获取**：挂 `afterAttack`（造成伤害用 `result.damage`、击杀用 `defenderDead`）+ `siteCaptured`（占领）。**金帐先例：不依赖 unitKilled**（GH-09 未对齐，killer 暂 null）。
2. **精锐死亡检测**：同样用 `afterAttack` 的 `defenderDead`——defender 是马穆鲁克精锐且死亡即触发 eliteLost。**不需要 unitKilled、不需要新埋点**。注意：战斗外的单位死亡（如有）不在覆盖内，交付报告说明即可。
3. **士气影响战斗数值**：挂 `beforeAttack`（payload 含 `result`，可改伤害；HRE 已用此模式改过 result）。**注册顺序注意**：before 类事件按 hre → goldenHorde → venice → mamluk 顺序叠加，HRE 的修改先于你的生效——同一次攻击若同时触发 HRE 步兵联动和你的士气加成，最终伤害 = 依次叠加。交付报告需说明叠加顺序影响。
4. **埃及"每回合额外回血"**：在 `turnStart` 里对符合条件的单位直接 `unit.hp = Math.min(unit.maxHp, unit.hp + N)`（**金帐先例：模块直接改单位字段是被允许的**，金帐 onBeforeMove 直接 `unit.move -= 1`）。unit 引用经 `ctx.game.units` 读取。**不需要 beforeHeal**。
5. **低士气"精锐恢复降低"——有接口缺口**：主回血流程 `healOwner` 在 main.js 内、`beforeHeal` 钩子未实现（GH-06 排期中），你**无法在回血时把量改小**。处置（三选一，交付报告必须说明选了哪个）：
   - a) **降级登记**（推荐，参照金帐 GH-04 先例）：本轮实现"高士气经验更快 + 骑兵首攻增强 + 低士气新生兵攻击下降"，"恢复降低"写入已知问题待 GH-06；
   - b) 在 turnStart 检查低士气精锐并**不**额外回血（只做"不加血"，不干预主流程）；
   - c) 报告主对话申请 beforeHeal（本轮不实施）。
6. **"骑兵第一次攻击增强"的语义**：请自己定义并测试（例如"每回合首次攻击 +N"或"开局后首击 +N"），在交付报告写明口径。
7. **士气为模块级状态**：用 `syncGameRef`（对比 `ctx.game` 引用变化自动 reset，金帐/威尼斯先例），不依赖主对话记得清理。

## 5. AI 行为边界（重要，避免悄悄改 AI）

- **自动部分（经验、V1/V2 升级、士气增减、死亡惩罚、埃及回血）对 AI 同样生效**——这是设计意图（马穆鲁克 AI 也会养精锐），与威尼斯被动机制对 AI 生效一致。

## 9. 前三个联盟的经验教训（避免重复踩坑）

1. **钩子签名以 factionRegistry 实现为准**：一律 `system[hook](ctx, payload)`（契约 v1.3 已修正文档，但不要照任何旧签名写）。
2. **"钩子改 payload 字段"必须回 main.js 核实引用语义**：harness 自己构造 payload 会假绿。`incomeCalculated` 是引用传递（main.js 用 `incomePayload` 对象 emit 后读 `incomePayload.amount`）；`beforeAttack` 的 `result` 同理（HRE 已实测可改）。改完在 harness 里用与 main.js 相同的对象传递方式模拟，别用字面量。
3. **tickStatuses 必须传全量单位 id**（`game.units.map(u => u.id)`）：status.js 对不在列表者执行删除，只传己方会误删敌方状态（金帐 raided 教训）。如果你用 status 系统，遵守此语义；如果是"永久成长"（veterancy），**不要用 status**——那是契约 §4 分类里的"永久成长"，用单位字段或模块级 Map。
4. **跨局状态自己闭环**：模块级 Map/Set 必须绑 `syncGameRef` 自动 reset。
5. **BFS/寻路陷阱**：8 连通 BFS 会用对角线偏移"绕过"你想让它穿过的地形（威尼斯教训）。测"河流/城市附近"判定时，直接构造数据测目标函数，别依赖路径搜索。
6. **决策 fallback 是第一项**：每个决策的第一项必须是"不行动/默认"，无头 sim 自动选它 = 默认局零变化。
